# 磁力快推备份与恢复方案

状态：方案建议，尚未实现。适用于 `scripts/easy-copy.user.js`。

## 建议

采用 **NAS WebDAV 自动备份 + JSON 文件导入/导出**。数据在插件之外保留副本，重装暴力猴和脚本后仍可恢复。先做文件恢复能力，再接入自动备份。

已有 qBittorrent NAS 地址不等于已有备份服务。需要在 NAS 上单独启用 WebDAV，提供备份目录及仅能访问该目录的账号；通过 HTTPS 或可信私有网络连接。

## 当前情况与恢复边界

- 脚本收集的是磁力链接，不是所有复制的文字。目前列表通过 `GM_setValue` 保存在脚本管理器内。
- 停用脚本通常不会删除已保存的数据；重新启用即可读取，但停用期间无法采集或执行备份。
- 卸载暴力猴、删除脚本或清除扩展数据，应按内部数据可能丢失处理。
- 撤销和重做记录只存在于当前页面内存，刷新页面后不会保留。
- 推送成功或判定重复后，链接会从当前列表中删除，并覆盖持久化列表。只备份最新列表，可能最终只得到空列表。
- 外部备份只能恢复到最近一次成功备份。离线期间新增但尚未备份的数据，无法保证在立即卸载后找回；设置内应能查看最近成功备份时间，并可主动导出文件。
- 现在已经删除且没有其他副本的历史记录无法凭空恢复；首次启用备份以现存列表为起点。

## 备份内容

| 内容 | 用途 |
| --- | --- |
| 当前列表 | 恢复尚未处理的磁力及原有顺序 |
| 完整收集档案 | 保留收集过的磁力、首次收集时间和处理状态；推送成功或从当前列表移除后仍保留 |
| 格式版本、生成时间、设备标识、数据修订信息 | 兼容升级、选择恢复时间点及处理并发写入 |

档案保存原始磁力链接，并使用标准化资源 hash 识别重复；无法取得 hash 时退回按链接去重。当前列表中的删除操作与档案记录分开保存，避免同步或恢复时让已处理记录自动重新出现在待推送列表。

默认不备份 qBittorrent 密码、WebDAV 密码或登录会话。重装后重新配置连接即可。完整档案长期保留；可清理旧快照，但不能因此删除档案中的早期记录。

## 自动备份规则

1. 采集或编辑后先保存到本地。连续变动在约 3 秒内合并，持续变动时最长约 15 秒发起一次备份；无变化不请求 NAS。
2. 上传失败保留待重试数据，按递增间隔重试；下次脚本运行时继续。备份失败不阻塞复制和正常使用。
3. 多标签页合并重复上传。写入同一个远端文件时，使用服务端支持的条件写入检测版本冲突，重新读取、合并后重试，不能用旧页面数据直接覆盖新数据。服务端不支持条件写入时，使用唯一文件名追加快照，不能无条件覆盖唯一副本。
4. 保留可恢复的历史快照，例如近 30 天每日版本，以及推送清理或批量删除前的版本。先成功写入新备份，再轮换旧快照；NAS 可再用自身快照机制保护备份目录。
5. 首次配置、重新安装或本地为空时，先检查远端备份，显示恢复入口，避免空列表覆盖已有备份。
6. 页面只在设置中展示“最近备份时间”“立即备份”“恢复备份”等用户需要的信息，不将重试队列和同步实现细节放到主面板。

## 恢复流程

1. 重新安装暴力猴与脚本后，配置 WebDAV，或选择之前导出的 JSON 文件。
2. 校验格式与内容，预览备份时间、当前列表条数和档案条数；格式错误时保留现有数据。
3. 默认合并恢复并按 hash 去重。已推送或已移除的链接保留在档案中，不自动再次推送。
4. 如选择按某个快照替换当前列表，先保存现有数据的恢复点；用户也可从档案中挑选链接重新加入列表。
5. 成功恢复后保存本地，并在自动备份启用时同步合并后的数据。

## 实施顺序与验证

第一步：增加完整收集档案和 JSON 导入/导出。文件脱离插件保存，成本最低，但手动导出仍有遗忘风险。

第二步：增加 WebDAV 配置、自动备份、失败重试、历史版本和恢复入口。需要 NAS 的 WebDAV 地址与备份目录，不要求更改现有 qBittorrent 服务。

验证重点：推送后仍能找回链接、刷新后档案仍在、重复导入不重复新增、损坏文件不覆盖数据、离线重试、多标签并发不覆盖、新安装空列表不覆盖远端，以及隔离浏览器配置中的卸载重装恢复。

不建议只额外写一份网页 `localStorage`：它按网站隔离且可能被清理，不适合作为全局备份。也不承诺“选一次本地文件夹后可在所有网站永久静默写入”，因为文件授权存在浏览器、来源和安全上下文限制。文件导出适合作为兜底，跨站自动备份优先使用 NAS。
